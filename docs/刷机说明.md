# 构建、安装与恢复

## 适配范围

仅面向 RDP-G01-W 小纸 Pico：ESP32-S3、16 MiB Flash、8 MiB PSRAM、4.7 英寸墨水屏。当前配置沿用 120 MHz Flash / PSRAM，适配 Zbit ZB25VQ128（JEDEC `0x5E4018`），没有覆盖其他料号。该实验性时钟组合存在温度漂移风险；不把启动成功当作温升或长时稳定验收。

默认 USB 安装只接受两种已识别布局：

- 下表的 Folio 七分区布局。
- [官方固定提交的四分区布局](<https://github.com/MindReset/read_pico_firmware/blob/6a247cc94420b85c650b32a6b2c063a360070eee/partitions_16M.csv>)：仅 nvs、phy_init、factory、storage，四项位置和大小完全相同。

ThingsOS、其他第三方固件及未知布局不自动迁移。不能凭 ESP32-S3 型号或 16 MiB 容量就认定可刷。

| 分区 | 地址 | 长度 |
| --- | --- | --- |
| nvs | `0x9000` | `0x5000` |
| phy_init | `0xE000` | `0x1000` |
| factory | `0x10000` | `0x400000` |
| storage | `0x410000` | `0x500000` |
| otadata | `0x910000` | `0x2000` |
| ota_0 | `0x920000` | `0x300000` |
| ota_1 | `0xC20000` | `0x300000` |

## 浏览器安装

使用桌面版 Chrome / Edge 等支持 Web Serial 的浏览器，通过 HTTPS 访问[官网](<https://qmqsu.github.io/folio/>)。Safari、Firefox 和大多数手机浏览器不支持此通路；仍可阅读说明和下载发行材料。

1. 手动确认机身型号，用数据线连接，关闭其他串口程序。
2. 选择有签名的已发布通道；核对版本及四段范围，向导先校验 P-256 签名、镜像结构与 SHA-256。
3. 选择串口并检测 Flash 型号、安全状态和分区；加密/Secure Boot、未知芯片或布局拒绝写入。
4. 需要完整备份时，先按手动方式读取 16 MiB Flash，验证传输摘要并计算 SHA-256，将备份保存到自己电脑中。备份包含潜在账号/网络信息，**不要公开上传**。TF 卡的重要书籍和 `.folio` 记录另行备份。网页一键安装不强制下载全片备份。确认启动槽切换，官方布局迁移还需额外确认。
5. 写入后由设备逐段计算 MD5 并与签名镜像比对，再核对 NVS/PHY 和字体资源区的设备端 MD5 未变；串口正常关闭后才报告成功。遇到取消或断线时保留“结果未确认”的含义，不将重新连接误报为写入成功。

默认没有 erase-all、merged 镜像或字体写入。取消不等于已经写入的段会被自动回滚；电源或 USB 中断可能需要使用完整备份恢复。生产签名防止接收伪造的网络发行，不替代供电保障，也不限制所有者用自己构建的源码恢复设备。

官网没有签名清单时明确显示尚未发布并禁用安装，不使用示例或未签名镜像兜底。

## 分段镜像

| 发行内容 | 地址 | 用途 |
| --- | --- | --- |
| `bootloader.bin` | `0x0` | 启动程序 |
| `partition-table.bin` | `0x8000` | Folio 布局 |
| `folio.bin` | `0x10000` | 首装 factory 应用 |
| `ota_data_initial.bin` | `0x910000` | 重置 OTA 启动选择 |

**不要把应用写到 `0x0`。** 这四段不会主动覆盖 NVS 或 storage，但 USB 重装会重置启动选择。若只更新应用，必须先核实当前启动槽；不能把 `0x10000` 当作任意设备当前应用地址。

发行工具不生成 merged 镜像。旧开发包可能含有 merged，填充区会影响 NVS；不应混用到当前官网安装流程。

## 设备在线更新与 TF 回退

带在线更新功能的 Folio 可在设置页手动检查稳定通道。需要已保存的 Wi-Fi、正确时钟、可用 TF 卡和足够电量；网络不通不会触发自动刷机。

清单经发布者签名验证后才接受；下载完成后再验证大小、SHA-256、芯片、应用描述及版本。用户确认安装后写入未运行的 OTA 槽；完整结束、取消和电量复查通过后才切换启动目标。新的应用初始化检查成功后确认启动，否则按引导程序回滚机制处理。真实掉电/回滚行为必须单独做设备验收。

取消并非瞬间完成：HTTP 响应阶段有仅中断 socket 的监督任务，TLS 对象仍由 worker 独占清理。建立连接前的 DNS 仍使用 SDK 同步 IPv4 查询；固定配置下理论重试预算约 21 秒，可能需等待其剩余时间及网络清理。这不是实机时延保证，也不承诺全链路 50 毫秒取消。DNS/连接/响应头完成前不创建本次暂存文件；实际断电、拔卡和 PMU 时序仍需单独验收。

GitHub 无法访问时，可使用手工 TF 路径：

1. 从可信发行材料取出应用并在电脑验证，将它保存为 TF 卡根目录的 `update/folio.bin`；把对应 SHA-256 文本保存为 `update/folio.bin.sha256`。
2. 也可通过设备无线传书上传这两个文件；不要上传 bootloader 或分区表冒充应用。
3. 退出传书，进入固件更新页的本地模式，核对版本、大小、哈希后确认安装并重启。

离线通路的 SHA-256 不是发布者签名；由设备所有者负责可信来源。只接受普通 ESP-IDF ESP32-S3 / Folio 应用，最大 3 MiB，不接受其他项目或 merged。

## 字体区不随应用更新

storage 可能已有其他内部数据。独立字体资源使用其中 5 MiB，首次覆盖须重新核对布局、备份整个区域并单独明确确认。不能因为当前程序没有挂载 FAT 就把它视为空白。

默认 USB 与应用 OTA 均不安装资源。没有资源包时应用原宋体仍可使用，其他记住的字体选择会临时回退；不应为“让字体正常”擅自覆盖 storage。OFL 许可和修改说明须随独立资源一起提供。

## 从源码构建

使用 ESP-IDF v6.1（发行固定 commit 见[发布协议脚本](<../tools/release_manifest.py>)）及其工具清单指定的 ESP32-S3 编译器。

```sh
. "$IDF_PATH/export.sh"
sh tools/idf.sh build
```

[tools/idf.sh](<../tools/idf.sh>)默认输出到 `${TMPDIR:-/tmp}/folio-readpico-build`；可用 `FOLIO_BUILD_DIR` 指定。不要提交本地 `sdkconfig`、SDK 安装目录或构建缓存。

发布使用独立 SDKCONFIG，并以 [sdkconfig.release](<../.github/sdkconfig.release>)关闭 USB 调试；本地开启调试的二进制不能作为公开发行。

完整重建即是替换 EPDiy 后重新链接的首选方法；发行还附带保留符号与重定位的静态库、链接脚本、配置及许可。见[许可清单](<../LICENSES.md>)。

## 恢复

优先保留安装前完整 Flash 备份、其 SHA-256，以及明确适配当前设备的恢复方法。恢复整机备份同样会恢复其中的 NVS/账号数据，不应使用他人的备份。

需要恢复官方固件时，遵循[官方构建与刷机说明](<https://github.com/MindReset/read_pico_firmware/blob/6a247cc94420b85c650b32a6b2c063a360070eee/README.zh-CN.md>)，使用匹配的完整布局和分段镜像；不要将某个应用替换成整机恢复。进入下载模式的按键操作应以硬件官方说明为准。

TF 卡数据不因内部 Flash 更新而主动擦除，但其他固件未必识别 Folio 进度格式。对故障恢复、实体屏显示和功耗，不以主机截图代替设备实测。
