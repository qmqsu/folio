# 0.8.40-dev：跨系统刷入与字体/白屏修复

日期：2026-11-20。针对用户反馈的「其他系统刷入后网页一键刷机不可用」「内置和 TF 卡字体无法加载」「导入书籍后白屏」。

## 修复内容

- 官网快速刷入仍只接受 Folio 七分区；新增对 ThingsOS 0.3.9 固定六分区布局的识别。它必须通过 `/folio/migrate/` 完整备份 16 MiB、下载证据、单独确认替换旧系统后才能写入；写前用设备端 MD5 复核整片内容仍与备份一致。其他未知布局仍只备份。
- `font_raster_alloc()` 在 PSRAM 分配失败后回退普通堆。此前 PSRAM 耗尽时，字体对象可打开但所有字形绘制失败，UI 忽略失败返回值，可能留下白底。
- 系统字体救援在目标字体和宋体失败后，依次尝试其他内置资源，再走普通 `/fonts` 扫描。这样 `/folio-fonts/` 内经固定长度和 SHA-256 验证的黑体、楷体、圆体也能参与救援，保留内置 ID 和圆体 Symbols 回退语义。

## 验证

- 字体文本、真实大字体、PSRAM 单独耗尽及双堆耗尽故障注入通过。
- 字体资源 2,991,787 项检查、卡回退 75,366 项检查、字体包 31,323 项检查通过。
- UI 732 次呈现通过，含内置资源救援；阅读、上传回归通过。
- 官网 124 项测试、类型检查、构建及无串口浏览器测试通过；ThingsOS 正常迁移与备份后变化拒绝均有替身回归。
- ESP32-S3 固件构建通过，应用仍小于 3 MiB OTA 槽。

## 边界

本轮没有连接实机，也没有用户白屏时的串口回栈或触发书籍样本。上述结果证明已修复两个主机可复现机制，不宣称覆盖所有书籍、字体格式、TF 卡故障或硬件启动原因。 ThingsOS 迁移仅完成模拟测试，不能当作真实设备迁移验收。
