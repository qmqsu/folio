# 公开分发核查（0.8.32 开发阶段）

本记录说明工程核查范围，不是律师意见或对全部法域的合规保证。自研代码的 MIT 已由项目所有者确认；它不替代任何第三方原许可。

## 已核对的材料

- 官方板级组件保留原 Apache-2.0 版权与许可；EPDiy 裁剪分支单独保留 LGPL-3.0-or-later、修改说明及完整源码。根目录[许可清单](<../LICENSES.md>)明确各范围。
- 原宋体和四个派生字体/补字文件保留 OFL、原作者版权、固定来源和修改说明。派生主名使用 Folio，不冒充原字体或原作者背书。独立资源不进入默认写入集合。
- 发行工具从实际构建描述读取 SDK 组件目录，收集各组件与 SDK 根许可/版权；记录固定子模块提交。对无独立许可文件的组件，仍需检查源码中的单独声明，根 Apache 不能覆盖相反声明。
- 工具链原始许可集合包括 GCC Runtime Library Exception、GPL 原文、picolibc/newlib 等声明。收集到许可证并不意味着其中每个工具都被链接，也不意味着应用整体改为该许可。
- 对应源码使用逐文件白名单，并验证每个字节属于指定 Git 提交。私有密钥、设备备份、账号资料、历史实机日志、本地 SDKCONFIG 和缓存不公开。
- LGPL 材料设计包括完整应用/EPDiy 源码、固定 SDK/工具链信息、发布配置、链接脚本与保留符号/重定位的静态库；去除调试路径不应破坏重新链接能力。所有者可自行构建并通过本地文件或 USB 安装修改版，不要求生产签名密钥。

## 必须在固件发行前完成

1. **网站依赖已完成本轮核对**：esptool-js 0.7.1 / esp-flasher-stub v1.2.2，S3 stub 的运行字段与上游对应，完整许可和固定源码见[可读声明](<../site/public/third-party-licenses.txt>)。以后依赖更新须重做，不可仅沿用网站 MIT。
2. 最终白名单隐私审查、字体覆盖检查，以及公开工作树中干净构建的精确源码/二进制对应验证。
3. 实际运行发行打包器，核对可读许可、source、relink、来源清单与其签名是否完整；不可仅凭脚本存在勾选通过。
4. 硬件验收与法律材料分开：USB、OTA、回滚、物理屏幕和温升没有验收时，不能晋升稳定版。

[发行门禁记录](<../.github/release-legal.json>)在这些核查完成前保持 false。官网可以先展示真实状态，但不会用未签名或虚构固件填充下载入口。
